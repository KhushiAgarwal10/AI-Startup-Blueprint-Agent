# 🚀 Startup Blueprint AI

> **AI-powered startup blueprint generator** built with Python Flask, Bootstrap 5,  
> and **IBM Granite on watsonx.ai** — deployable on IBM Cloud Code Engine.

---

## ✨ Features

| Feature | Details |
|---|---|
| **18-Section Blueprint** | Executive Summary → Investor Pitch, fully generated by IBM Granite |
| **Idea Validation** | 5-dimension quick check before full generation |
| **Business Readiness Score** | 0–100 score with colour-coded badge |
| **PDF Export** | Download a polished, branded PDF instantly |
| **Blueprint History** | Last 20 blueprints saved in session with stats dashboard |
| **Dark / Light Mode** | Full dark mode with localStorage persistence |
| **Typing Effect** | Progressive markdown rendering with animated cursor |
| **Sections Quick-Nav** | Jump to any of the 18 sections with one click |
| **Mobile Responsive** | Bootstrap 5 grid, tested on 320px–4K viewports |
| **AGENT_INSTRUCTIONS** | Fully customisable agent persona, tone, safety rules, and scoring rubric |
| **IBM Cloud Ready** | Port 8080, Gunicorn WSGI, non-root Docker user, Code Engine health probe |

## ⚙️ Local Setup

### 1. Prerequisites

- Python 3.10+
- An [IBM Cloud account](https://cloud.ibm.com/registration)
- A [watsonx.ai project](https://dataplatform.cloud.ibm.com/)

### 2. Clone & install

```bash
git clone <your-repo-url>
cd startup-blueprint
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### 3. Configure credentials

```bash
cp .env.example .env
```

Edit `.env` and fill in:

```env
WATSONX_API_KEY=<your IBM Cloud API key>
WATSONX_PROJECT_ID=<your watsonx.ai project ID>
WATSONX_URL=https://us-south.ml.cloud.ibm.com   # choose your region
FLASK_SECRET_KEY=<random string>
```

### 4. Run locally

```bash
python app.py
```

Open [http://localhost:8080](http://localhost:8080)

## 🤖 Customising Agent Behaviour (`AGENT_INSTRUCTIONS`)

All agent behaviour is controlled by the `AGENT_INSTRUCTIONS` dict in [`config.py`](config.py).  
**No code changes needed** for the most common customisations — just edit the strings:

| Key | What it controls |
|---|---|
| `persona` | Agent name, role, and expertise framing |
| `tone` | Communication style (formal, casual, encouraging…) |
| `creativity` | How lateral / unconventional the suggestions are |
| `domain_expertise` | Business domains the agent specialises in |
| `output_quality` | Depth, specificity, and data requirements |
| `safety` | Content restrictions and legal disclaimers |
| `regulatory_guidance` | Government scheme and legal advice guardrails |
| `scoring_rubric` | How the 0–100 Business Readiness Score is calculated |
| `blueprint_sections` | Order and names of the 18 blueprint sections |
| `validation_criteria` | 5 dimensions used for quick idea validation |

**Example — change tone to ultra-concise:**
```python
"tone": (
    "Be extremely concise — one sentence per bullet point maximum. "
    "Use bullet points exclusively. No preamble."
),
```

**Example — focus on FinTech only:**
```python
"domain_expertise": (
    "You specialise exclusively in FinTech: payments, lending, wealthtech, "
    "regtech, insurtech, and open banking. Apply deep regulatory knowledge "
    "for SEBI, RBI, FCA, SEC, and MAS markets."
),
```

**Model & generation tuning** via `.env`:
```env
GRANITE_MODEL_ID=ibm/granite-3-3-8b-instruct
AGENT_TEMPERATURE=0.7      # 0 = conservative, 1 = creative
AGENT_MAX_TOKENS=4096      # higher = more detailed blueprints
AGENT_TOP_P=0.9
```

## ☁️ Deploy to IBM Cloud Code Engine

### Prerequisites
- [IBM Cloud CLI](https://cloud.ibm.com/docs/cli) with Code Engine plugin
- Container registry (IBM Container Registry recommended)

### Steps

```bash
# 1. Login to IBM Cloud
ibmcloud login --sso

# 2. Target your region and resource group
ibmcloud target -r us-south -g Default

# 3. Login to IBM Container Registry
ibmcloud cr login
ibmcloud cr namespace-add <your-namespace>

# 4. Build and push image
docker build -t us.icr.io/<namespace>/startup-blueprint-ai:latest .
docker push us.icr.io/<namespace>/startup-blueprint-ai:latest

# 5. Create Code Engine project (skip if existing)
ibmcloud ce project create --name startup-blueprint-project
ibmcloud ce project select --name startup-blueprint-project

# 6. Create registry secret (for private images)
ibmcloud ce secret create-registry \
  --name icr-secret \
  --server us.icr.io \
  --username iamapikey \
  --password <IBM Cloud API key>

# 7. Deploy the application
ibmcloud ce application create \
  --name startup-blueprint-ai \
  --image us.icr.io/<namespace>/startup-blueprint-ai:latest \
  --registry-secret icr-secret \
  --port 8080 \
  --cpu 1 \
  --memory 2G \
  --min-scale 1 \
  --env WATSONX_API_KEY=<key> \
  --env WATSONX_PROJECT_ID=<project_id> \
  --env WATSONX_URL=https://us-south.ml.cloud.ibm.com \
  --env FLASK_SECRET_KEY=<secret> \
  --env FLASK_ENV=production

# 8. Get the public URL
ibmcloud ce application get --name startup-blueprint-ai --output url
```

> **Tip**: Use [IBM Cloud Secrets Manager](https://cloud.ibm.com/docs/secrets-manager)  
> or Code Engine secrets instead of `--env` for production credentials.

## 🌐 API Reference

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Landing page |
| `GET` | `/chat` | Blueprint generation UI |
| `GET` | `/dashboard` | Blueprint history dashboard |
| `POST` | `/api/generate` | Generate full 18-section blueprint |
| `POST` | `/api/validate` | Quick 5-dimension idea validation |
| `POST` | `/api/download-pdf` | Download blueprint as PDF |
| `GET` | `/api/health` | Health check (Code Engine liveness probe) |
| `GET` | `/api/history` | Retrieve session history as JSON |
| `POST` | `/api/clear-history` | Clear session blueprint history |

### POST `/api/generate`

```json
// Request
{ "idea": "An AI tool that helps nurses document patient interactions 3x faster." }

// Response
{
  "success": true,
  "blueprint": "## Executive Summary\n...",
  "readiness_score": 82,
  "startup_name": "NurseNote AI",
  "error": null
}
```

## 🔒 Security Notes

- Never commit `.env` to version control (it's in `.dockerignore` / `.gitignore`)
- Rotate `FLASK_SECRET_KEY` before production deployment
- Use Code Engine secrets or IBM Secrets Manager for credentials in production
- The app enforces a 2 MB request size limit and 3 000-character idea cap
